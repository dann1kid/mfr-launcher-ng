# Требования к клиенту

Что клиент обязан уметь. Правила ведения документа — раздел «Требования к клиенту» в `AGENTS.md`.

- **БТ-n** — функциональное бизнес-требование: что получает игрок.
- **БТ-n.m** — технический подпункт: как это работает и чем проверяется.
- **К-n** — корнер-кейсы и приоритеты между функциями.
- **«На будущее»** — запланированные функции, пока не обязательные.

«Настройки» бывают трёх видов, и у каждого своё требование:
- опции сборки — БТ-4;
- настройки движков и их утилит — БТ-5;
- настройки самого клиента — БТ-11.

## БТ-1. Установка игры

Игрок нажимает «Установить игру» и получает игру, готовую к запуску.

- Клиент проверяет, хватит ли места, скачивает сборку и показывает, сколько осталось.
- Обрыв сети, пауза и выход из клиента не начинают загрузку заново: она продолжается с места остановки.
- После установки стоят средние пресеты MGE XE и OpenMW, а MGE XE прописан в реестре.

Подпункты:

- **БТ-1.1.** Файл скачивается во временный `.part` и докачивается с места обрыва. Перед переносом на место он сверяется по sha256, а сам перенос атомарный: под окончательным именем лежит только целый проверенный файл.
- **БТ-1.2.** Пауза отменяет загрузку. «Продолжить» перезапускает ту же задачу и пропускает файлы с верной суммой. Ни пауза, ни продолжение не очищают папку игры.
- **БТ-1.3.** После установки клиент:
  - ставит пресет «Средний» для MGE XE и OpenMW;
  - запускает настройщик MGE XE и через несколько секунд закрывает его — так MGE XE прописывается в реестре.

  Если настройщика нет, установка всё равно считается успешной.
- **БТ-1.4.** Установка ничего не удаляет из папки игры, пока не получен манифест устанавливаемой версии.
- **БТ-1.5.** Игра считается установленной только после успешной установки. Неудачная или прерванная задача признак установки не меняет.

## БТ-2. Обновление игры

Клиент сам замечает, что сервер отдаёт другую версию сборки, и обновляет игру по кнопке «Обновить игру». Другая версия бывает и более ранней, если сервер откатил выпуск.

- Скачивается только изменённое, убранные из сборки файлы удаляются.
- Выбранные опции, настройки движков, сохранения и скриншоты остаются как были.

Подпункты:

- **БТ-2.1.** Удаляется только файл, который был в прежнем манифесте и исчез из нового. Перекачивается только файл манифеста с несовпавшей sha256. Файлов вне манифеста клиент не трогает.

## БТ-3. Проверка целостности

Игрок запускает проверку, и клиент возвращает файлы сборки в исходное состояние.

- Испорченные и пропавшие файлы сборки скачиваются заново.
- Прежде чем сбросить файл с настройками, клиент спрашивает игрока (К-4).
- Файлы, которых нет в манифесте, проверка не трогает.
- Отдельный режим полной очистки удаляет всё, чего нет в манифесте, и только после явного подтверждения игрока.

Подпункты:

- **БТ-3.1.** Проверка сверяет по sha256 обязательные части манифеста и скачанные пакеты опций. Несовпавшие и пропавшие файлы перекачиваются.
- **БТ-3.2.** Перед полной очисткой клиент показывает, что будет удалено, и удаляет только после подтверждения.
- **БТ-3.3.** Без установленной игры проверка целостности недоступна.

## БТ-4. Опции сборки

Игрок выбирает, какой контент сборки ставить: в каждой группе опций — один вариант.

- Группы и варианты — ровно те, что описаны в схеме версии.
- Описания и картинки вариантов видны без скачивания пакета.
- Пока игрок не выбрал другой вариант, стоит вариант по умолчанию из схемы.
- Пакет группы можно скачать заранее и удалить.
- Если пакет варианта не скачан, применение сначала скачивает его.
- Смена варианта меняет только свою группу.
- Выбор сохраняется после обновлений и проверки целостности.

Подпункты:

- **БТ-4.1.** Группы, варианты, описания, картинки и вариант по умолчанию берутся только из схемы версии; в клиенте их нет.
- **БТ-4.2.** Пакет — группа манифеста: варианты других групп не скачиваются и в игру не копируются.
- **БТ-4.3.** Применение варианта и удаление пакета отменой не прерываются. Откат применения не удаляет файлов, до которых не дошёл.

## БТ-5. Движки и их утилиты

Игрок настраивает движок, которым играет, и запускает его утилиты из колонки движка.

**Оригинальный движок:**
- пресеты MGE XE («Мощный», «Средний», «Слабый», «Древний компьютер») и ручной настройщик MGE XE;
- Morrowind Code Patch;
- штатный лаунчер Morrowind;
- порядок загрузки плагинов, который клиент поддерживает сам.

**OpenMW:**
- пресеты конфигурации;
- лаунчер OpenMW.

**Для обоих движков:**
- перед применением пресета собственные настройки игрока сохраняются копией и возвращаются выбором «Свои настройки»;
- обновление игры настройки движков не трогает.

Подпункты:

- **БТ-5.1.** Клиент выставляет даты основных ESM/ESP, по которым оригинальный движок определяет порядок загрузки. Это происходит при каждом старте с установленной игрой и после каждой смены версии.
- **БТ-5.2.** Пресет копируется из шаблона как есть: для MGE XE — `MGE.ini`, для OpenMW — четыре файла конфигурации. Единственная правка — в шаблоне `openmw.cfg` строка-заместитель заменяется путём к папке игры. Других правок конфигов клиент не делает.
- **БТ-5.3.** Нужна ли копия «Своих настроек», решается по конфигурации, найденной при открытии окна пресетов, а не по последнему клику.
- **БТ-5.4.** Morrowind Code Patch запускается с запросом прав администратора.

## БТ-6. Запуск игры

- «Играть» в колонке движка запускает игру этим движком: оригинальным Morrowind или OpenMW.
- Для запуска не нужны ни сеть, ни сервер.

## БТ-7. Руководство, FAQ и сообщество

- Руководство к сборке открывается с сайта, а без сети — из папки игры.
- Кнопки FAQ, форума и сообществ проекта открывают их страницы в браузере.
- Окно «Помочь проекту» показывает реквизиты, утверждённые владельцем.

## БТ-8. Версии и линии игры

Клиент работает с несколькими версиями и линиями игры.

- Какие версии и линии доступны этой установке, в том числе бета, решает сервер; клиент показывает то, что тот отдал.
- Игрок может выбрать другую линию. Переход — после подтверждения с предупреждением о сохранениях.
- Если линии игрока на сервере больше нет, клиент сам переводит его на доступную линию (К-2).
- Клиент подсказывает о новой линии и запоминает отказ.
- Игрок видит свой идентификатор установки и может его скопировать.

Подпункты:

- **БТ-8.1.** Идентификатор установки создаётся один раз и переживает обновления клиента и игры. В запросы он уходит только там, где его объявляет контракт.
- **БТ-8.2.** Если сохранённое значение линии не разбирается как линия, его заменяет линия установленной игры, а без установленной игры — первая линия из перечня сервера. Замена происходит до первого запроса версии и до любой задачи. Пока перечня нет, задачи, которым нужна линия, не запускаются.
- **БТ-8.3.** Новая линия предлагается диалогом, а отказ запоминается до появления следующей.

## БТ-9. Самообновление

- Клиент сам узнаёт о своей новой версии. Игрок нажимает «Обновить лаунчер», клиент заменяет свой exe и перезапускается.
- После обновления всё на месте: игра установлена, линия и опции те же, настройки клиента не сброшены.
- Обновление идёт только вперёд, отката нет. Скачанный файл проверяется до замены.

## БТ-10. Сеть и недоступный сервер

- Клиент работает через доступный регион раздачи, а игрок может выбрать регион сам.
- Короткие сбои клиент переживает повторами, связь восстанавливается без перезапуска.
- Без сети установленная игра запускается, и есть режим offline.

Подпункты:

- **БТ-10.1.** На ответы 5xx и сетевые ошибки клиент отвечает повтором с растущей паузой на каждом уровне: запросы к серверу, манифесты, файлы. Таймаут — это ошибка с повтором, а не пауза.
- **БТ-10.2.** Если сжатая копия не скачалась, скачивается исходный объект.
- **БТ-10.3.** Связь восстанавливается периодической проверкой, без перезапуска. Недоступный сервер игрок видит как недоступный, а не как «Обновлений нет».
- **БТ-10.4.** Регион — сохранённый выбор игрока, иначе замер `/ping`. Пока регион не выбран, запросов к серверу нет.
- **БТ-10.5.** Адресов хранилищ в клиенте нет: адрес раздачи приходит в ответе сервера.

## БТ-11. Главное окно и настройки клиента

**Главная вкладка:**
- колонки двух движков;
- одна главная кнопка с действием, нужным сейчас (К-1);
- прогресс задачи;
- версия игры и путь к ней.

**Вкладка настроек клиента:**
- линия (БТ-8), «Исправить» (БТ-3), регион и режим offline (БТ-10), ограничение скорости загрузки, «Сворачивать в трей», версия клиента;
- каждая показанная настройка работает и сохраняется после перезапуска.

**Поведение:**
- ошибки понятны, и клиент от них не падает;
- окно сворачивается в трей;
- в фоне клиент не наращивает нагрузку на процессор и память.

Подпункты:

- **БТ-11.1.** Настройки, состояние, журналы и переопределение адресов лежат рядом с exe. Рабочий каталог процесса ни на что не влияет.
- **БТ-11.2.** Из одной папки работает один экземпляр. Второй запуск показывает окно первого и завершается.
- **БТ-11.3.** Интерфейс только на русском. Названия и описания вариантов приходят в схеме.

## БТ-12. Поддержка и совместимость

- У клиента есть журнал, который игрок передаёт в поддержку.
- Клиент ходит к серверу только по действующему контракту.
- У клиента один номер версии.

## Общие свойства

- Клиент работает на Windows x64.
- С сервером обменивается только по защищённому соединению.
- Пишет только в папку игры и свои папки.

## Корнер-кейсы и приоритеты

- **К-1. У главной кнопки несколько поводов сразу.** Показывается старший: обновление клиента, затем установка игры, затем обновление игры, затем новая линия. Во время задачи кнопка показывает её ход и вторую задачу не запускает. После неудачной задачи кнопка снова предлагает то действие, которое не удалось.
- **К-2. Версии или линии игрока больше нет на сервере.** Решает ответ на запрос версии текущей линии. То, что линии нет в перечне, само по себе поводом не является.
  - Сервер отдаёт в линии другую версию — это обычное обновление (БТ-2), линия не меняется.
  - Сервер отвечает «такой линии нет» — клиент без выбора переводит игрока на первую линию из перечня и прежнюю больше не запрашивает:
    - с установленной игрой — сообщает о смене линии с предупреждением о сохранениях, а игра обновляется до новой линии штатно, главной кнопкой;
    - без установленной игры — главная кнопка предлагает установку в новую линию;
    - перечень пуст — клиент позже повторяет запрос перечня, установленная игра запускается.
  - Сервер отвечает «пока нечего отдать» — это К-3, линия не меняется.
  - В выборе линии текущая линия видна, даже если её нет в перечне.
- **К-3. В линии временно нечего отдать** (ответ «пока нет версии»). Установленная игра запускается, линия не меняется, клиент сам повторяет запрос позже. Главная кнопка не предлагает ни установку, ни обновление в эту линию. Если сервер не отдаёт и состав установленной версии, проверка целостности и пакеты опций сообщают об этом понятным текстом.
- **К-4. Игрок изменил файл из состава сборки:** Morrowind.exe после Code Patch, Morrowind.ini, MGE.ini или настройки MWSE. Проверка целостности спрашивает, восстанавливать ли его, и ответ «нет» сохраняет файл.

## На будущее

- Библиотеки, нужные Morrowind, ставит сам клиент в привязке к версии игры.
- Клиент работает не только на Windows, но и на macOS и Linux.
